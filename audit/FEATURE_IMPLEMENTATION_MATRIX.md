## Supplementary changes after the baseline audit

The matrix includes the five-repository dense retrieval pilot, failure-informed retry, bounded streaming sandbox output, and immutable GitHub-import provenance. The full command `.venv\Scripts\python.exe -m pytest --tb=short -rs` returned 179 passed and 3 skipped in 5.73 seconds on 17 November 2026; all skips require Windows symlink permission. The live public-import smoke is separate from the deterministic Docker retry and does not measure repair quality. The five retrieval labels remain weak changed-file proxies; see the reproducibility record for raw evidence and limits.

## Priority findings

1. Describe the system as deterministic Text Analytics + TF-IDF default retrieval + optional dense/model proposals + bounded Docker tests. Most stages are not independent LLM agents.
2. Before a repair-effectiveness study, hold issue revisions, model settings, context budget, patch validation, sandbox tests, and outcome labels constant across arms.
3. Improve proxy annotation with independent file/function relevance review before interpreting or generalizing retrieval metrics.
4. Complete a formal adversarial Docker isolation review; non-root execution and configured controls are live-smoke-tested but are not a formal isolation guarantee.
5. Remove unsupported literature-gap claims. Recent work already covers query reformulation, retrieval representations, and localization-to-repair effects.
6. Keep controlled fixtures, blocked runs, and benchmark outcomes as separate evidence classes.
