# Contribution candidates and evidence

The contribution areas below are engineering and research candidates, not claims of field novelty. Existing literature already studies query reformulation, lexical/dense/hybrid retrieval, repository-level repair, and the relationship between localization and repair.

| Candidate | Current evidence | Status | Remaining evidence |
|---|---|---|---|
| C1. Preserve the original report while producing inspectable deterministic retrieval queries. | The devmind-query-v1 transformer retains the original text and records four generated query variants, extracted terms, identifiers, hints, category, and version. Unit tests cover the deterministic behavior. | Implemented engineering feature; not claimed as novel. | Independent review can check whether transformation traces are understandable and useful. |
| C2. Measure how query enrichment changes repository localization. | A paired five-instance SWE-bench Lite development pilot compared four variants against one changed-file proxy per issue. TF-IDF Recall@3 moved from 0.60 to 0.80 after keyword/identifier enrichment; Recall@1 and Recall@5 were unchanged. | Preliminary descriptive evidence only. Labels are unreviewed proxies and n=5. | Independently review labels, increase sample size, retain paired per-issue results, and report uncertainty only when justified. |
| C3. Compare lexical, semantic, and hybrid retrieval under comparable budgets. | The paired pilot compared TF-IDF, BM25, lexical RRF, Sentence Transformers cosine, and lexical-semantic RRF on identical snapshots and labels. | Five-case descriptive comparison only. Dense cosine Recall@5 was 0.40 versus 0.80 for TF-IDF and dense index construction took 594.737 seconds on this CPU. Labels remain unreviewed proxies. | Independently review labels, expand the sample, and repeat with controlled context budgets and hardware measurements. |
| C4. Keep candidate patches traceable to evidence and bounded test feedback. | The validator, bounded orchestrator, Docker-only disposable testing, and human-review gate are implemented. Historical controlled fixture runs have selected tests passing. | Implemented workflow with narrow synthetic evidence; not a novel research contribution. | Current Docker availability, independent patch review, and broader same-issue evaluation are still required. |
| C5. Relate localization quality to downstream repair outcomes. | The comparison runner implements shared baseline and candidate testing protocols. There are no matched model-backed arms or independently adjudicated repair outcomes. | Deferred. | Fix model, prompt, context budget, snapshots, tests, timeout, patch budget, and outcome adjudication across all arms; use official grading for SWE-bench resolution claims. |

## Safe current description

DevMind is a local repository bug-analysis prototype with deterministic issue preprocessing, default TF-IDF retrieval, optional model-backed patch proposals, and constrained candidate testing when Docker is operational. A five-case lexical retrieval pilot has been run against unreviewed changed-file proxies. The pilot is exploratory and does not establish exact localization, semantic quality, repair accuracy, or generalization.
