# Architecture

## Current data flow

```text
Bug report -> Task Analyzer -> Python AST / JavaScript lexical indexer -> Lexical Retriever
           -> local sparse TF-IDF vectors / cosine retrieval
           -> Evidence-constrained Investigator -> JSON report
           -> bounded Code Agent <-> Docker copy / apply-diff / pytest or node --test
           -> conservative Reviewer gate -> JSON report
```

`pipeline.run_analysis` coordinates analysis and evidence creation. It defaults to TF-IDF, or accepts a local embedding provider/model path to retrieve top-k evidence by cosine similarity. A supplied saved index is reused only when its embedding model and indexed chunks match the current repository; otherwise it is rebuilt. `orchestrator.run_repair` provides the optional bounded patch/test feedback loop. `cli.main` parses command-line input and emits JSON. The root-level `streamlit_app.py` accepts local folder paths or public GitHub URLs, provides the styled analysis workflow, and shows evidence, progress, review state, history, and JSON download. For a GitHub URL, `github_repo.py` resolves the default branch through the GitHub API to a full commit SHA, fetches the archive by that immutable SHA, and records the commit plus downloaded ZIP SHA-256 in report metadata. The bounded extraction output then goes to the same local pipeline. The indexer uses Python's AST parser or lexical JS/TS brace scanning, including scripts embedded in HTML, and never imports or executes target modules. Evidence includes relative file path, symbol, source line span, and a similarity score whose metric is included in the report.

## Modules

- `models.py`: immutable analysis, source chunk, evidence, and investigation records; mutable `RunReport` supports serializable run output.
- `logging_config.py`: JSON structured logging with timestamp, level, logger, message, and safe event fields.
- `analyzer.py`: dependency-free normalization and preprocessing, snake/camel-case tokenization, frequency-ranked keywords, code-like component hints, and exact-token category scoring. It is explainable rule-based text analytics, not a trained classifier.
- `github_repo.py`: validates public `github.com` repository URLs, reads repository metadata and the selected branch's full commit SHA, downloads a capped ZIP by commit SHA from GitHub's archive host, computes the archive SHA-256, and rejects unsafe paths, symlinks, oversized files, excessive archive contents, Windows reserved device names, and alternate data stream paths. It never runs repository code.
- `indexer.py`: recursive Python/JavaScript/TypeScript/HTML source discovery with generated-directory pruning; Python uses AST function/class spans, while JS/TS uses lexical brace-counting for braced functions. Inline scripts in HTML/HTM are scanned as JavaScript and retain original HTML line numbers. No target code or markup is executed. It stops once the configured file limit is exceeded. Symlinked directories and file links resolving outside the selected root are skipped. Malformed and unreadable files are skipped.
- `retrieval.py`: provides in-memory TF-IDF cosine, Okapi BM25, and reciprocal-rank fusion indexes. Fusion requires the same ordered traceable chunks; fused scores are rank-fusion scores, not similarities.
- `query_variants.py`: emits four versioned deterministic queries for the retrieval ablation and retains the original report, normalized text, keywords, identifiers, component hints, heuristic category, and exact generated query.
- `retrieval_metrics.py`: computes binary file-level Precision@k, Recall@k, MRR, and nDCG@k; rejects missing relevance labels.
- `retrieval_experiment.py` / `retrieval_evaluation.py`: evaluate four query conditions over matched TF-IDF, BM25, lexical-RRF, and optional local Sentence Transformers indexes. Optional semantic mode adds dense cosine and lexical-semantic RRF. The CSV CLI separates labels from sanitized issue inputs, rejects unknown columns, verifies supplied snapshot hashes before indexing, collapses chunk results to files, and records source spans, latency, index-build time, and an approximate source-context token count. A model supplied for the evaluation run is reused across repository snapshots.
- `embeddings.py`: defines the replaceable `EmbeddingProvider` contract, a deterministic feature-hash provider for tests (not semantic), and an optional local-only Sentence Transformers adapter. It supports the model dimension APIs in the installed supported versions.
- `vector_index.py`: embeds traceable chunks, normalizes vectors for cosine similarity, and saves a safe NumPy matrix plus ordered JSON chunk metadata. It uses FAISS inner-product search when installed and exact NumPy cosine search otherwise. CLI and Streamlit opt in through a local model folder; both default to TF-IDF.
- `investigator.py`: formats retrieved evidence as leads or optionally asks the configured chat provider for hypotheses. Structured results must cite supplied evidence IDs and include uncertainty; malformed output is rejected. Pipeline falls back to deterministic leads on provider errors.
- `providers.py`: replaceable provider interface, structured request/response records, deterministic fake provider, and OpenAI-compatible chat adapter using the standard library. It classifies invalid responses, rate limits, and transport errors, applies bounded retries (configurable with `DEVMIND_LLM_MAX_RETRIES`) and configurable timeouts, and can send Ollama's `think: false` option when `DEVMIND_LLM_DISABLE_THINKING` is enabled.
- `sandbox.py`: Docker-only pytest or Node test runner (`DEVMIND_TEST_RUNNER`). It creates a temporary copy, excludes common credential files/directories and generated directories, runs as UID/GID `10001:10001`, disables network access, drops all Linux capabilities, prevents privilege gain, mounts a read-only root with bounded tmpfs, limits memory/CPU/processes/time, validates candidate diffs, checks patch paths and symlinks, optionally applies a diff inside the container, and records whether the configured test runner was reached. Separate reader threads continuously drain stdout/stderr while retaining at most the final 4,000 characters per stream and tracking truncation and the execution marker independently.
- `failure_analysis.py`: parses bounded retained sandbox output into failing test names, stack frames, error classes, and retrieval terms. Raw stdout/stderr are kept in the local attempt record and are excluded from structured provider feedback.
- `docker/sandbox/Dockerfile` is the Python 3.12/Git/pytest image; `docker/sandbox-node/Dockerfile` is the Node 22/Git image for built-in Node tests. Both images receive the repository copy at run time.
- `planner.py`: deterministic bounded checklist based on extracted issue features.
- `pipeline.py`: coordinates analysis, planning, evidence serialization, and optional one-shot patch generation.
- `code_agent.py`: turns evidence, optional investigation findings, repository metadata, and bounded prior test feedback into a provider prompt. It validates unified-diff structure, rejects no-op diffs and unsafe paths, and can restrict changes to paths present in retrieved evidence. Valid proposals can be saved outside the source repository; they are never applied on the host.
- `orchestrator.py`: caps repair attempts at three, assigns run-local evidence IDs, and records each attempt's evidence, selection reason, patch digest, exact test command/runner/timeout, test result, and structured failure analysis. After a failed test it searches the unchanged source snapshot with TF-IDF using extracted test/function/path/error cues, then supplies only structured failure feedback to the next model request. OS-level Docker launch and temporary-workspace errors become blocked sandbox outcomes.
- `reviewer.py`: strict status gate; requires the candidate patch's own isolated tests to pass and still leaves final review to a person.
- `evaluation.py`: validates raw run labels, appends raw JSON Lines records, and computes failure/test-pass rates, label accuracy, and process means with explicit denominators. Missing data stays null.
- `evaluation_runner.py`: runs LLM-only, RAG-only, and agentic RAG on each same issue. The unmodified test suite runs once per issue as a shared preflight; all valid candidates are then tested in the same Docker-only sandbox protocol. Records include both test outcomes, actual provider calls, prompt-size estimates, sandbox outcomes, latency, per-attempt repair audit data for the agentic arm, and null resolution labels.
- `evaluation_cli.py`: reads issue-set JSON, runs the comparison, and writes an aggregate report plus optional append-only JSONL records.
- `evaluation/retrieval/` and `datasets/`: contain a five-instance SWE-bench Lite development-split pilot with separate proxy labels, opaque runtime IDs, pinned base snapshots, and content-hash verification. Both lexical and pinned-model dense results are preserved as separate raw runs; labels remain unreviewed changed-file proxies.
- `cli.py`: command-line interface.
- `streamlit_app.py`: Streamlit workflow selector and results view. AppTest verifies page rendering; full patch and repair interactions require a configured model provider and Docker.
- `stats.py`: parses saved run reports into dashboard statistics. The dashboard calls these “test-passing candidates”; a passing candidate test still requires human review and is not labelled a verified fix. Test pass rate remains unavailable when no tests ran. Dashboard rendering uses defaults for missing newer KPI fields to keep a stale imported stats module from crashing the history view during updates.
- `streamlit_app.py`: presents the guided workflow and keeps technical detail behind expanders. The repository-source selector is outside the submission form so switching to GitHub immediately changes the input to a URL field. On submit, public ZIP snapshots enter the local static-analysis pipeline and are never executed. The fixed monochrome theme uses the supplied galaxy video as the page background, with hover/focus feedback on controls and a lift/glow hover state on the primary submit button. `static/galaxy.mp4` and `static/galaxy-poster.jpg` are served through Streamlit's `/app/static/` endpoint.
- `api.py`: optional FastAPI backend with a loopback middleware, bounded Pydantic requests, an explicit allowed-repository-root list, offline analysis, and capped in-memory run history. It does not expose patch or test execution over HTTP.
- `browser-extension/`: unpacked Manifest V3 launcher for Chrome/Brave. It opens the configured DevMind web UI and passes the active `github.com` repository URL in the query string after the user clicks the extension. It does not access private repositories or write to GitHub.

See [ACCEPTANCE_CHECKLIST.md](ACCEPTANCE_CHECKLIST.md) for requirement-by-requirement status and the release gate. On 2026-10-21, the live path ran with Ollama 0.40.5 and Qwen3 1.7B: the model generated the synthetic fix, Docker applied it to a disposable copy, and pytest returned 2 passed. The Reviewer kept the result at `tests_passed_review_required`.

## Trust boundaries

Repository files are treated as data during analysis. Model output is untrusted. Unified diffs must be structurally valid, modify at least one file, target supported relative Python/JavaScript/TypeScript paths, and (for the evidence-grounded agent) target only retrieved paths. Candidate patch output must be outside the source tree. The Code Agent preserves meaningful whitespace, recounts hunk lines, and removes trailing non-diff model text. Before testing, the runner checks target and parent paths for symlinks and verifies resolved targets remain inside the repository. It writes the mounted diff with LF line endings and a final newline. In the isolated container, `git apply --unidiff-zero` accepts compact model hunks; path and evidence restrictions still apply, and the patch is tested only against a disposable copy. The proposed diff is not applied to the original checkout. The test report distinguishes candidate patch and baseline runs. A passing test suite is evidence only for that specific test environment and does not prove absence of regressions.

## Important exceptions and limits

- Empty bug reports and invalid limits raise `ValueError`.
- `index_repository` raises for invalid repository paths or file-limit overflow; unreadable/invalid individual source files are skipped.
- `OpenAICompatibleProvider.complete` raises typed `ProviderUnavailable` errors on missing settings, malformed responses, rate limits, and failed provider requests. Saved run reports record successful candidate test runs for one Python and one JavaScript synthetic fixture; these are narrow demonstrations and still require human review.
- `run_tests` raises `SandboxUnavailable` when Docker or the image setting is missing; the CLI and orchestrator convert this and OS-level Docker launch errors into non-executed blocked test results.
- The API rejects remote clients, external Host/Origin values, and repository paths outside `DEVMIND_API_REPOSITORY_ROOTS`. It binds to loopback from its own entry point. Recent reports are in-memory only.
- Docker Desktop 29.9.1 was started and responded during the 17 November 2026 verification. In the controlled synthetic QuickCart-like fixture, the baseline Node test failed, a known candidate patch passed, and a deterministic two-attempt repair run failed once, retrieved the test file as new evidence, then passed on retry. The selected fixture stayed unchanged. This is an integration smoke, not a public-repository result or a security proof.
- Local Qwen3 1.7B did not produce a verified repair for the synthetic cart issue: its first structurally valid diff failed `git apply`; another request timed out at 180 seconds. The comparison runner has not been executed with a live provider. The Sentence Transformers adapter has not been exercised in the interactive app; default app retrieval remains TF-IDF unless a model path is supplied. There is no reranker, repository cloning, or reviewer model. Evaluation labels and token/cost data remain missing until independently supplied or exposed by a provider. The API exposes offline analysis and run history only; patch generation and test execution are not exposed over HTTP.
- Failure-informed retry and bounded streaming output have unit and live synthetic coverage. Both supplied images and the sandbox invocation use UID/GID `10001:10001`; Python and Node smokes verify baseline failure, candidate pass, and unchanged source trees. The live deterministic retry does not prove model repair quality, and the sandbox controls are not a formal isolation guarantee.
- Evaluation `run_failure_rate` is an operational process metric, not bug-fix accuracy. It counts blocked statuses, statuses ending in `_failed`, and exhausted repair loops. `resolution_accuracy` is null until both ground-truth and prediction labels are independently recorded.

# SWE-bench Lite adapter

`devmind.swebench` reads exported JSONL task metadata, validates repository slug and hexadecimal base commit, requires explicit instance IDs, downloads a bounded archive for that pinned commit through the public GitHub importer (up to 20,000 files and 500 MiB extracted), skips symlink entries without creating them on the host, and records how many links were skipped. The skip may reduce the indexed source context. It passes issue text plus the extracted source tree to the ordinary static analysis and patch-proposal pipeline. Retrieval is limited to four snippets by default and can be adjusted with `--top-k 1..8`; prompt context defaults to 1,500 characters per snippet and can be adjusted with `--context-chars 500..5000`. The normal app keeps its existing 5,000-character per-snippet context. It writes predictions in the SWE-bench harness JSONL shape and separate run notes. It does not install a training dataset dependency, import repository modules, apply candidate patches, or execute target tests. The official harness remains responsible for isolated grading.

TF-IDF query tokens also receive conservative singular variants (`models` → `model`, `dependencies` → `dependency`, `PKs` → `pk`) to improve recall when bug reports use plurals and code identifiers do not. The variants affect retrieval queries only.
