# Learning guide

## What this first implementation does

DevMind reads a natural-language bug report, normalizes and tokenizes its text, splits snake_case and camelCase identifiers, removes common stop words, ranks terms by frequency, extracts code-like component hints, and applies transparent exact-token rules to assign a coarse issue category. It can read a local directory or download a bounded public GitHub ZIP archive. For GitHub URLs, it resolves the default branch to a full commit SHA, downloads by that immutable ID, and records the commit and archive SHA-256 in the report. The archive importer rejects path escapes and symlinks and does not execute source. DevMind uses Python ASTs and lexical function scanning for several languages, then ranks code chunks and reports the matching paths and line ranges. It labels findings as leads, because matching words do not prove root cause.

For retrieval experiments, `query_variants.py` preserves the input and emits a reproducible four-condition ablation. The analyzer remains rule-based. These query variants do not mean the project has a trained classifier or a learned query-reformulation model.

An optional model provider can suggest a unified diff. A diff is only a proposal. If Docker is available, the sandbox copies the repository, applies that diff inside a network-disabled container with all Linux capabilities dropped and privilege gain disabled, and runs the configured pytest or Node `node --test` command there. The selected original repository is not edited. If required infrastructure is missing, the output records a blocker.

## Example data flow

1. Input: `parse_value crashes on empty input`.
2. `analyze_issue` may extract `parse_value`, `crashes`, and `empty` as terms and classify the report as an exception.
3. `index_repository` finds a function such as `parse_value` and stores `parser.py`, line span, symbol name, and source text.
4. `retrieve` ranks chunks whose path, function name, or source contains the issue terms.
5. `investigate` returns a source-cited lead and explicitly says causal verification is still needed.
6. If configured, a model may return a candidate diff. Tests may only verify it when the isolated runner applies that same diff and returns real test output.
7. With `--repair`, DevMind parses retained sandbox output for test names, stack frames, and error classes. It uses those cues to search the unchanged source snapshot again with TF-IDF, then sends a structured summary (not raw stdout/stderr) with the newly ranked evidence to the next model request. The loop is capped at three attempts and stops on success or a provider/sandbox blocker.

## Files and core functions

- `analyzer.py` — `analyze_issue(text, max_keywords=12)` returns `IssueAnalysis` with normalized keywords, a heuristic issue category, and code-like component hints. Empty input or a non-positive/non-integer limit raises `ValueError`. Category scoring is rule-based and has not been measured on an independently labelled corpus.
- `github_repo.py` — `parse_public_repository_url(url)` accepts a public `github.com` repository URL; `download_public_repository(url, workspace)` reads repository metadata, fetches the default-branch archive, and safely extracts a size-limited snapshot. It does not clone private projects or execute repository code.
- `stats.py` — `load_report_history(...)` reads saved JSON reports; `compute_dashboard_stats(records)` aggregates test-passing candidate counts and test pass rate. When there are no executed tests, pass rate is `None` because the denominator is missing.
- `indexer.py` — `index_repository(repository, max_files=5000)` returns `CodeChunk` records for Python AST function/class nodes, braced JavaScript/TypeScript functions, and braced functions inside HTML/HTM inline scripts; HTML chunks preserve source page line numbers. Target code is not executed. Invalid roots or too many files raise `ValueError`; source parse/read errors are skipped. It prunes generated directories and external symlinks and never imports target code.
- `logging_config.py` — `configure_logging(verbose=False)` configures JSON logs; `JsonLogFormatter` formats each event with a timestamp and structured fields.
- `retrieval.py` — `TfidfIndex`, `BM25Index`, and `ReciprocalRankFusion` return ranked, traceable evidence. TF-IDF cosine and BM25 are lexical methods; RRF combines ranks without treating scores as comparable similarities. Fusion checks that every index uses the same ordered chunks.
- `query_variants.py` — `build_query_variants(text)` produces raw, normalized, keyword/identifier, and structured queries with the full transformation trace and version `devmind-query-v1`.
- `retrieval_metrics.py` — `score_file_ranking(ranked_files, relevant_files)` computes Precision@1/3/5, Recall@1/3/5, MRR, and nDCG@1/3/5. An empty label set is rejected rather than scored as zero.
- `retrieval_experiment.py` — `build_retrievers(...)` creates paired TF-IDF, BM25, and lexical-RRF indexes; an explicit local model path adds dense and lexical-semantic RRF. `evaluate_retrieval_methods(...)` crosses these methods with four query variants and reports file metrics, latency, source-context size, and evidence.
- `retrieval_evaluation.py` — `devmind-retrieval-evaluate --inputs ... --labels ... --output ...` loads sanitized issue inputs, indexes each base snapshot, scores separate labels, and writes JSONL records. It rejects unknown columns and does not execute the indexed repository.
- `investigator.py` — `investigate(evidence)` returns evidence-linked findings, cautious hypotheses, and uncertainties.
- `planner.py` — `create_plan(analysis, max_steps=5)` returns an ordered bounded checklist; it does not execute steps.
- `providers.py` — `OpenAICompatibleProvider.complete(prompt)` returns provider text or raises `ProviderUnavailable`. Configure endpoint, model, timeout, and optional Ollama thinking control through process environment variables; a key is optional for local compatible servers. Patch generation sends retrieved source snippets to that configured service.
- `sandbox.py` — `run_tests(repository, candidate_patch=None, image=None, timeout=None, test_runner=None)` returns executed status, pass/fail, the final 4,000 characters of each output stream, truncation flags, exit code, and container UID/GID; select pytest or Node `node --test` with `DEVMIND_TEST_RUNNER`. Set the matching image variable (`DEVMIND_DOCKER_IMAGE` for Python, `DEVMIND_NODE_DOCKER_IMAGE` for Node) before starting the app. Separate reader threads drain both pipes so retained output memory stays bounded. It raises `SandboxUnavailable` if Docker/image configuration is missing. It revalidates the diff and checks target/parent symlinks before applying a patch only in the container. The command and images enforce UID/GID `10001:10001`, drop all capabilities, and set `no-new-privileges`; these controls do not prove complete isolation.
- `docker/sandbox/Dockerfile` — builds the Python or Node test image with Git. The repository is copied into the container at run time instead of baking source code into an image.
- `code_agent.py` normalizes hunk counts and removes non-diff text after a candidate diff while preserving meaningful context whitespace. `sandbox.py` writes mounted patch text with LF line endings and restores one final newline. Candidate patches are applied and tested only in a Docker copy. A live deterministic retry smoke passed after one failing attempt and failure-informed retrieval. A later Qwen3 1.7B cart proposal did not apply; a follow-up model request timed out. See the exact run records under `reports/`.
- `reviewer.py` — `review_candidate(candidate_patch, test_result)` refuses approval without a passing result for that exact candidate patch; passing tests still require human review.
- `stats.py` — aggregates saved reports for the Run history tab. The UI uses safe defaults for newer optional statistic fields so a stale Streamlit process does not fail the entire dashboard.
- `streamlit_app.py` — the repository-source selector stays outside the form so the local-path/GitHub-URL field updates as soon as the user switches it. Submission downloads a public GitHub archive locally, statically indexes it without running repository code, and retrieves evidence for the entered bug report. Optional semantic retrieval settings and technical report detail stay collapsed. The primary submit button uses high-contrast label and hover styling. The monochrome galaxy video is decorative and does not affect analysis.

The evaluation dataset contains five SWE-bench Lite development instances with four query variants and separate changed-file proxy labels. Lexical and pinned CPU dense runs are preserved under evaluation/raw_runs/. Dense cosine scored below TF-IDF on the five unreviewed proxy paths and required substantially more CPU index-build time. These results are descriptive only; see `reports/experiments/RESULTS.md` and `research/RESEARCH_GAP_ANALYSIS.md`.
- `evaluation.py` — `summarize_runs(records)` computes operational run-failure and test-pass rates, resolution accuracy where separate labels exist, and process means with explicit denominators. `write_run_records(path, records)` appends one JSON record per line.
- `evaluation_runner.py` — `run_comparison(issues, provider=None, max_attempts=2, output_path=None)` runs three conditions over the same issue inputs. The unmodified test suite runs once per issue, then each valid candidate is tested through the same Docker sandbox interface. Records include both test outcomes, actual provider/sandbox calls, prompt-size estimates, test output, and latency. Issue-resolution labels and token/cost values remain null when not independently observed.
- `evaluation_cli.py` — `main()` reads the issue JSON array and writes an evaluation JSON report plus optional JSONL raw run history.
- `providers.py` — `ChatRequest` validates prompt and temperature; `ChatResponse` stores normalized text and optional token counts. `OpenAICompatibleProvider` supports timeouts, up to three retries, typed errors, and JSON mode. `complete_json` checks that structured output is a JSON object before use. `DeterministicFakeProvider` returns queued text for repeatable tests.
- `investigator.py` — `investigate(evidence, issue=..., provider=...)` creates evidence-linked findings. With a provider, it sends a bounded set of snippets, then requires each hypothesis to cite a supplied evidence ID and include uncertainty. Invalid model output raises a typed error; the pipeline falls back to deterministic leads.
- `api.py` — `AnalyzeRequest` limits field sizes and top-k; `create_app()` registers health, analysis, and recent-run routes; `_resolve_allowed_repository()` enforces the configured root allow-list. The API binds to loopback and keeps only the newest 50 run reports in memory.
- `pipeline.py` — `run_analysis(issue, repository, limit=8, provider=None, generate_patch=False)` coordinates analysis and returns `RunReport`.
- `code_agent.py` — `generate_candidate_patch(issue, evidence, provider, test_feedback=None)` requests a unified diff grounded in the retrieved evidence and, on retries, the prior isolated test result. `validate_unified_diff` enforces valid relative `.py` paths, matching diff headers, valid hunks, and a real change; optional `allowed_paths` limits targets to retrieved evidence. `write_candidate_patch` saves a validated proposal outside the source repository.
- `failure_analysis.py` — `analyze_test_failure(result)` extracts bounded test names, source frames, error classes, and retrieval terms while keeping raw output out of the structured provider-feedback object.
- `orchestrator.py` — `run_repair(issue, evidence, repository, provider=None, max_attempts=2)` retries up to three times. A failed run triggers TF-IDF retrieval against the original repository and records each attempt's evidence IDs, evidence-selection reason, patch digest, test command/runner/timeout, result, and failure analysis. Raw sandbox output remains in the local audit record, not the next provider prompt. Unit tests and a live synthetic Docker retry cover this flow; the live retry used a deterministic provider, not an LLM.
- `cli.py` — `main()` defines the `devmind` command and writes JSON to stdout or `--output`.
- `streamlit_app.py` — Streamlit interface for choosing a local repository and workflow, viewing evidence/progress/results, and downloading the report. Page rendering is checked with AppTest; provider and Docker workflows need integration testing in an environment with those services.
- `embeddings.py` — defines `EmbeddingProvider.embed(texts)` and a vector dimension; `HashEmbeddingProvider` is deterministic for tests but has no semantic understanding. `SentenceTransformerProvider` loads an already-downloaded model folder only.
- `vector_index.py` — `VectorIndex(chunks, embedder)` embeds source chunks; `search(query, limit=8)` returns traceable `Evidence`; `save(directory)` and `load(directory, embedder)` persist and restore the index. It validates vector shape/finiteness and keeps row order aligned with chunk metadata.
- `pipeline.py` — `run_analysis(..., embedding_model_path=..., vector_index_directory=...)` opts into vector retrieval. It checks saved metadata and current AST chunks before reuse; changes cause a rebuild. `limit` configures top-k results. The default remains TF-IDF.
- `cli.py` and `streamlit_app.py` — expose the same optional local model folder, saved index folder, and top-k setting. The report labels the retrieval method and score metric.

## Tests and what they do not establish

The unit suite covers deterministic fake-provider responses, structured JSON validation, HTTP status classification, bounded retry behavior, timeouts, key redaction, patch structure and path validation, and sandbox path checks. Focused snapshot/model/evaluator tests on 17 November 2026 returned 13 passed in 0.70 second. A full suite after the latest source changes has not been run. Historical Python and JavaScript synthetic repair reports record selected tests passing; both require human review and are not general accuracy evidence. Earlier Windows test skips required symlink privileges.

Vector embeddings are lists of numbers that represent text. This implementation compares normalized vectors with a dot product, which equals cosine similarity. Keyword TF-IDF gives high weight to rare matching words; a real sentence embedding can place different wording near each other based on learned language patterns. FAISS is an optional library for fast vector lookup; exact NumPy search is the fallback. The saved matrix rows map by position to the JSON chunk records. Re-index after repository edits so embeddings and source metadata remain in sync.

Practical round-trip: call `index_repository('examples/buggy_project')`, construct `VectorIndex(chunks, HashEmbeddingProvider())`, then call `save('reports/local-index')`. `VectorIndex.load('reports/local-index', HashEmbeddingProvider())` restores the same mapping. This verifies storage and search plumbing only. A pinned all-MiniLM-L6-v2 model was loaded and evaluated on the five-case pilot; the measured result and resource cost are in reports/experiments/RESULTS.md. Hash embeddings remain test plumbing, not a semantic model.

Repository RAG flow: the pipeline combines the bug report and extracted hints into a query, embeds it with the same provider as the indexed code, searches the top-k vectors, and maps each result row back to its code chunk. It returns that chunk's path, symbol, lines, source snippet, and cosine similarity. This provenance lets a reviewer inspect the actual context before trusting an LLM proposal. The cache is refreshed when the provider identity or the indexed chunk list changes. An index folder inside the selected repository is rejected so analysis does not write into the source project.


## Viva questions

1. **Why use Python's AST instead of importing repository modules?** AST parsing inspects syntax and line locations without running repository initialization code.
2. **What does a source chunk contain?** A relative path, symbol name and kind, line range, and the source text for that symbol.
3. **What is the retrieval score?** The report labels its retrieval method. TF-IDF scores represent weighted term overlap; vector-index scores are cosine similarity for the configured embeddings. A score ranks evidence but does not prove a root cause.
4. **Does a retrieved function prove root cause?** No. It is a lead; execution evidence and tests are needed to support a causal claim.
5. **What is a unified diff?** A text format describing line-level file changes that tools can apply.
6. **Why must model output be treated as untrusted?** It may be malformed, incorrect, or contain unsafe changes; it must not run directly on the host.
7. **How is the original repository protected during tests?** DevMind copies repository data to a temporary directory and mounts that copy into Docker; a candidate diff is applied there.
8. **What does a passing test suite mean?** Only that the selected tests passed in that specific copied environment. It does not prove the bug is fixed in every case or that regressions are absent.
9. **Why disable container networking?** To reduce opportunities for test code to access external services or download additional code during execution.
10. **Why compare LLM-only, RAG-only, and agentic RAG, and why cap repair attempts?** Running the same issues with one model helps isolate workflow differences, while a small retry limit bounds cost and prevents endless repair loops. All three conditions now send valid candidate patches through the sandbox. A real same-issue study still needs a configured provider, working Docker, pinned snapshots/settings, and independently reviewed resolution labels.
11. **How do saved vector rows stay linked to source evidence?** The metadata JSON stores chunks in the same order as rows in `vectors.npy`; search result row IDs index that ordered list.
12. **Why normalize vectors before using dot product?** It makes the dot product equal cosine similarity, so scores compare vector direction without being affected by vector length.
13. **Does the hash embedding prove semantic retrieval works?** No. It is a deterministic test double that hashes terms into fixed vector positions. Semantic quality must be checked with an actual language embedding model.
14. **What happens when a source file changes after indexing?** The saved index is a snapshot. Re-index and save again so vectors and source locations match current files.
15. **Why save JSON metadata and a non-pickle NumPy matrix?** JSON keeps source records inspectable, and `allow_pickle=False` avoids loading arbitrary Python objects from the vector file.
16. **What is top-k?** The maximum number of highest-ranked evidence chunks returned for a query. DevMind lets the caller set it and includes each result's cosine-similarity score.
17. **What does provenance mean in the report?** It means every retrieved code snippet points back to its repository-relative path, symbol, and source line range, so a person can inspect the exact source.
18. **Why give retrieved evidence to a patch model?** Relevant source narrows the context for its suggestion and lets a reviewer check whether the proposal is grounded in actual code. It does not prove the model's fix is correct.
19. **What is a context window?** It is the amount of text a language model can process in one request. Top-k bounds how many code chunks are selected, but chunk size and prompt length still need management.

## Study again

Review Python regular expressions and dictionaries, AST node line numbers, filesystem-relative paths, JSON serialization, vector normalization, cosine similarity, cache invalidation, HTTP timeouts, subprocess arguments, Docker mounts, and the difference between a hypothesis, a proposed patch, and a test-verified result.

The provider unit tests mock HTTP responses. Separately, an end-to-end synthetic repair contacted local Ollama 0.40.5 with `qwen3:1.7b`; this verifies one local provider call and repair only. To use the local server, follow the PowerShell setup in the manual. The adapter never retries indefinitely: rate-limit and server/transport failures retry at most three times after the first request, with short bounded waits; set `DEVMIND_LLM_MAX_RETRIES=0` to disable retries for slow local inference. Configuration and local-provider setup remain user-managed; no paid service or model download is required for offline workflows.

Model investigation is opt-in with `--model-investigation` in the CLI or the matching checkbox in Streamlit. Returned `E1` style IDs map to the current run's evidence order, not permanent database IDs. The pipeline records whether the result came from the model or deterministic fallback. This is a hypothesis generator; a cited source still needs human review and behavioral tests.

The FastAPI backend test uses actual ASGI HTTP requests for health, allow-listed analysis, run history, and rejection of remote clients. Analysis routes are unavailable until `DEVMIND_API_REPOSITORY_ROOTS` is configured. The default process binds to loopback; the route middleware also blocks non-local clients and origins. The Streamlit UI does not yet call the API backend.

The [acceptance checklist](ACCEPTANCE_CHECKLIST.md) separates implemented/tested modules from integrations that need external services. A real Docker run verifies container startup, copy/mount behavior, and actual pytest output; it still does not substitute for a real model call or prove isolation against every threat.

# Evaluating repair with SWE-bench Lite

SWE-bench Lite supplies real issue statements paired with a repository name and a `base_commit`. The commit matters: analyzing the current default branch can expose code that did not exist when the issue was reported and makes results incomparable. DevMind's adapter uses the exact commit archive for static evidence retrieval and patch generation. Its output is a prediction, not a verified repair. The benchmark harness applies predictions and runs tests inside Docker; only its recorded grading results count as benchmark outcomes. Start with a few explicit instances and preserve a held-out subset if you tune prompts or retrieval. In smoke runs, Astropy was downloaded and indexed but the local Qwen3 1.7B model timed out; Django was downloaded with four symlinks skipped, but the model response was not a valid diff. Neither run produced a candidate to grade.

The first Django retrieval ranked unrelated test snippets above the implementation because the report used plural words such as `models`, `dependencies`, and `PKs`, while source tokens were singular. Query-only singular variants now improve lexical recall without changing source indexing or the deterministic text-classification labels. The regression test captures that ranking failure; real-world retrieval quality still needs benchmark measurement.

The patch prompt now also tells the model to preserve values needed by an operation until that operation succeeds. This guards against a common repair error: clearing an object identifier before using it to delete the corresponding database row. It is a prompt constraint, not a correctness guarantee.
